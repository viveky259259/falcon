# Falcon Coverage Uplift — Design

**Date:** 2026-05-25
**Status:** Draft, awaiting approval
**Target version:** falcon 0.4.0 → next

## Goal

Raise Falcon's automated test coverage to **≥90% line coverage** across the library
crate, working bottom-up from the lowest-covered modules. The work is open-ended
and spans multiple sessions; each session ends at a commit with a measurable
coverage delta.

## Non-Goals

- Branch / region / MC/DC coverage. Line coverage only for this initiative.
- 100% coverage. The last 10% is mostly entry points, server loops, and
  exit-on-error paths that cost more than they're worth.
- New features, rule additions, or refactors. Test-only changes, plus the
  *minimum* refactor needed to make a unit testable (extract a pure helper, lift
  IO behind a trait, etc.).

## Tooling

**Coverage tool:** `cargo-llvm-cov` (instruments via `-C instrument-coverage`,
uses LLVM source-based coverage, works on darwin, fast, stable Rust).

Install (one-time):

```
cargo install cargo-llvm-cov --locked
rustup component add llvm-tools-preview
```

Standard invocations used by this initiative:

```
# Per-module table sorted ascending — drives the worklist.
cargo llvm-cov --workspace --summary-only

# Full HTML report for drilling into uncovered lines.
cargo llvm-cov --workspace --html --output-dir target/llvm-cov/html

# LCOV for CI / external dashboards.
cargo llvm-cov --workspace --lcov --output-path target/llvm-cov/lcov.info

# Fail CI below the threshold (used once we're stable at ≥90%).
cargo llvm-cov --workspace --fail-under-lines 90
```

A thin Make-style helper (`scripts/coverage.sh`) will wrap the common commands so
contributors don't memorize flags.

## Scope: What Counts Toward the 90%

The 90% threshold applies to the **library crate** (`src/lib.rs` and everything
it re-exports), not the binaries. Rationale: binaries are thin dispatchers; the
testable logic lives in the library.

### Hard exclusions (counted out of the denominator)

Marked with `#[cfg(not(coverage))]` gates or `// LCOV_EXCL_LINE` / `// LCOV_EXCL_START..STOP`
markers. Each exclusion gets a comment explaining *why* it's excluded.

- `src/main.rs` — CLI dispatch glue. Behavior verified through integration
  tests in `tests/`, not line coverage.
- `src/bin/falcon-lsp.rs`, `src/bin/falcon-mcp.rs` (if present) — server entry
  points / event loops.
- `fn main() {}` / `#[tokio::main]` shims.
- `eprintln!` / `colored` print branches inside Display impls and CLI reporters
  where the only thing under test is the format string.
- Generated code (tree-sitter grammar bindings if any).
- `unreachable!()` / `unimplemented!()` arms documented as defensive.

Everything else — rules, analysis passes, AI scoring, manage, dashboard logic,
api/lsp/mcp **handler logic** (not the loop itself) — counts.

## Architecture of the Test Work

### Per-module loop (one iteration ≈ one PR / commit batch)

1. **Measure.** Run `cargo llvm-cov --workspace --summary-only`. Sort modules
   ascending. Pick the lowest-covered module above the noise floor.
2. **Read.** Open the module's source. Identify testable pure functions vs.
   IO-bound code. If IO-bound code is untestable as-is, plan the minimum
   refactor (extract pure helper, inject filesystem trait, etc.).
3. **Write tests.** Prefer `#[cfg(test)] mod tests` colocated with the source
   (matches the existing convention in this repo). Use `tests/` only for true
   integration coverage that spans modules.
4. **Re-measure.** Confirm the module is at ≥90% (or excluded with comment).
5. **Commit.** One commit per module with message
   `test(<module>): cover <module> to N% (was M%)`.
6. **Update tracker.** Append a line to `docs/coverage-progress.md` (a simple
   ledger: date, module, before %, after %, commit SHA).

### Worklist source of truth

`docs/coverage-progress.md` — append-only ledger of completed modules with
before/after coverage and commit SHAs. Generated by hand at the end of each
session; not authoritative. The authoritative source is always a fresh
`cargo llvm-cov` run.

### Refactor budget

When a module is untestable without restructuring, the budget per module is:

- ✅ Extract a pure function from inside an IO routine.
- ✅ Add a small trait + `&dyn Trait` parameter to allow injection.
- ✅ Promote a private item to `pub(crate)` so tests can reach it.
- ❌ Re-architecting modules, renaming public API, splitting files.
- ❌ Anything that changes observable behavior. If a "refactor for testability"
  changes behavior, stop and brainstorm separately.

If a module *cannot* hit 90% within the refactor budget, document it in
`docs/coverage-progress.md` under "Deferred" with the reason. These get a
follow-up spec, not a workaround in this one.

## Components

### `scripts/coverage.sh`

Thin wrapper around `cargo llvm-cov`. Provides:

- `coverage.sh summary` — print sorted ascending per-module table.
- `coverage.sh html` — generate and open HTML report.
- `coverage.sh ci` — fail-under-90 invocation used in CI.
- `coverage.sh module <path>` — coverage for a single module file.

### `docs/coverage-progress.md`

Append-only ledger. One line per completed module:

```
| Date       | Module                         | Before | After | Commit  |
|------------|--------------------------------|--------|-------|---------|
| 2026-05-25 | src/rules/common/dead_code.rs  |  42%   | 94%   | abc1234 |
```

### `.github/workflows/coverage.yml` (deferred to last session)

Once the library is stable at ≥90%, add a CI gate that runs
`cargo llvm-cov --fail-under-lines 90`. Until then, CI changes are out of scope
(don't gate development on a number we haven't hit yet).

## Data Flow

There isn't one — this is test-only work. Each per-module iteration:

```
git pull → llvm-cov summary → pick lowest module
         → write tests → llvm-cov re-measure → commit → push
         → update ledger
```

## Error Handling

- `llvm-cov` install failure → document in README; halt initiative until fixed.
- A module that breaks under tests → revert the test changes, file an issue
  describing the latent bug, defer until fixed (a test that exposes a real bug
  is success, not failure — but don't merge red tests).
- Refactor exceeds budget → stop, mark module "Deferred", move to next.

## Testing Conventions (for the tests we add)

- **Location:** `#[cfg(test)] mod tests` inside the source file unless the test
  spans modules.
- **Naming:** `fn <function_under_test>_<scenario>_<expectation>()`. E.g.
  `fn parse_pubspec_missing_name_returns_err()`.
- **Fixtures:** Use `tempfile::TempDir` for filesystem fixtures, `serde_json::json!`
  for JSON. No new test-helper crates without explicit sign-off.
- **Assertions:** `assert_eq!` / `assert!` over `pretty_assertions` unless an
  existing module already imports it.
- **No mocks** for things we own. Inject traits or pass concrete values. Only
  mock at HTTP / process boundaries.
- **Determinism:** No tests that depend on wall-clock time, locale, or network.
  Hidden network calls in AI modules require a fake provider trait.

## Exit Criteria

The initiative is complete when **all** of these hold:

1. `cargo llvm-cov --workspace --summary-only` shows **≥90% line coverage**
   for the library crate.
2. All exclusions are commented with a reason.
3. `docs/coverage-progress.md` shows every module that was below 90% at the
   start of this initiative now meets the threshold or is documented as
   Deferred with a reason.
4. CI runs `cargo llvm-cov --fail-under-lines 90` on every PR (final session).
5. No tests are flaky on three consecutive `cargo test` runs.

## Open Questions

None blocking. The following will be decided during execution:

- Whether to wire coverage upload to Codecov / Coveralls. Default: no, unless
  the user asks for it.
- Whether `falcon_dart/` and `falcon-dart/` (Dart-side) get their own coverage
  initiative. Default: out of scope for this spec — Rust crate only.

## Approval

This spec is the contract. Per-session work executes against it. Any deviation
(scope creep, new exclusions, refactor-budget exceptions) requires updating
this doc first.
